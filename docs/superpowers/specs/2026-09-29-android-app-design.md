# Android App — Design

Date: 2026-09-29

## Goal

A sideloaded Android app of PulseRun whose voice and beep cues arrive on time
while the phone is locked or another app is in the foreground. The target
case is a treadmill session with YouTube playing in front: cues must duck
YouTube briefly, then let it return.

## Decisions

- **Why an app:** reliable background coaching only. Store presence, iOS and
  native polish are out of scope.
- **Android only**, installed by sideloading an APK.
- **One codebase:** the Svelte UI, `src/core/` and i18n are shared. The web
  build keeps deploying to GitHub Pages with unchanged behavior.
- **Capacitor 8 shell plus one custom Java plugin** (Java, because the Capacitor 8 Android
  template is Java-only). The native side owns the whole cue timeline (tones and voice), because the WebView's JavaScript
  is throttled or paused in the background. If this fails the success
  criterion below, the fallback is a full native rewrite (Kotlin + Compose).
- **Local builds first** (debug-signed, installed over USB). CI APK builds
  come later, only if this approach passes the phone test.

## 1. Architecture

### Shared timeline — `src/core/timeline.js` (pure, test-first)

```js
/**
 * @typedef {{ kind: 'tone', tone: CueKind, inMs: number }
 *         | { kind: 'speech', inMs: number, phaseType: PhaseType,
 *             seconds: number, extraKeys: string[] }
 *         | { kind: 'speech', inMs: number, finish: true }} TimelineEvent
 */
export function buildTimeline(session, workout, now, settings, { announceCurrent })
```

- Tone events are `filterCues(upcomingCues(session, workout, now), settings)`.
- A speech event at every phase start still ahead, with that phase's full
  length in `seconds` and `extraKeys` from `coachExtras(workout, i, voiceStyle)`.
- A finish speech event at the end of the workout.
- `announceCurrent: true` adds a speech event at `inMs: 0` for the current
  phase with its remaining seconds. This matches today's web behavior: the
  current phase is announced on start, on resume from the reload dialog and
  after a skip, and not after an in-app pause/resume or a settings change.
- A paused or finished session returns `[]`. With `voiceVolume` 0 there are
  no speech events.
- Events are sorted by `inMs`. At equal `inMs`, a tone comes before speech.

Core cannot import i18n, so speech events carry keys and parameters. The
controller turns them into text (`phaseLine()` and `t('cue.finish')`, as
today) before handing the timeline to the native engine.

### Cue engine seam — controller

The controller talks to one interface instead of `cuePlayer` + `speak`:

```js
/** @typedef {{
 *   start(session, workout, now, settings, { announceCurrent }): boolean,
 *   stop(): void,
 *   test(settings, sampleText, onDone): void,
 *   speaksInBackground: boolean,
 * }} CueEngine */
```

`test` plays the audio-sheet test: `sampleText` (if the voice has volume),
then the tones from `testSequence(settings)`, and calls `onDone` when
finished. The web engine takes over today's `testAudio()` sequencing; the
controller keeps building the sample line. The web engine ignores
`announceCurrent`, because its speech still comes from `tick()`.

- **Web engine** (`src/platform/webCueEngine.js`): wraps today's
  `createCuePlayer()` and `speak()`. `speaksInBackground: false`, so the
  controller keeps speaking from `tick()` as it does now. Behavior unchanged.
- **Native engine** (`src/platform/native/nativeCueEngine.js`): builds the
  timeline, resolves speech text via a text resolver the controller passes
  in at creation, and calls the native plugin. `speaksInBackground: true`, so
  `tick()` and `finish()` do not speak.
- The controller picks the engine once at startup with
  `Capacitor.isNativePlatform()`. If a native call fails, it switches to the
  web engine for the rest of the session so the workout still runs.
- The timer invariant still holds: pause, resume, skip, stop and settings
  changes call `stop()` and, if still running, `start()` with a fresh
  timeline. `start()` is still called from a user gesture.
- On finish, the web engine keeps its current grace period before
  `stop()`. The native service stops itself after the finish line plus its
  own grace period, so the controller does not stop it.
- Changing the language mid-run re-sends the timeline, so upcoming lines
  are spoken in the new language.
- The wake lock is skipped on native (the service holds a CPU wake lock).
  Share keeps its existing Web Share → clipboard fallback.

### Android project — `android/`

Generated by Capacitor and committed. Build outputs, `.gradle/`,
`local.properties` and the copied web assets are git-ignored.
`capacitor.config.json`: `appId: "io.github.willenjs.pulserun"`,
`appName: "PulseRun"`, `webDir: "dist"`. App icon: the Kinetic Blades logo.

Dependencies added: `@capacitor/core`, `@capacitor/cli`,
`@capacitor/android`. No other plugins.

## 2. Native side (Java)

### `CoachPlugin` (bridge, registered in `MainActivity` before `super.onCreate`)

- `start({ events, locales, notification })`: events with resolved text
  and volumes (`{ type: 'tone', atMs, tone, volume }` or
  `{ type: 'speech', atMs, text, volume }`), the voice locales in preference
  order, and the notification's channel name, title and text. Starts `CoachService` in the foreground and hands it the timeline.
- `stop()`: cancels pending events and stops the service.
- `test({ speech, tones, locales })`: plays the audio-sheet test sequence
  (the sample line, then the tones) and resolves when it has finished.
- `requestPermissions()`: asks for `POST_NOTIFICATIONS` (Android 13+) on the
  first workout start.

### `CoachService` (foreground service, type `mediaPlayback`)

- **Notification:** e.g. title "Semana 1 - Dia 1", text "Treino em
  andamento", both passed from JS. Tapping it reopens the app.
- **Clock:** on `start`, each event becomes an absolute
  `SystemClock.uptimeMillis()` target posted on a dedicated `HandlerThread`
  (uptime keeps pace with real time while the wake lock below is held). A partial wake lock is held until the finish event plus a
  grace period, so Doze cannot delay cues with the screen off. The timeline
  is replaced on every pause, resume, skip or settings change, so drift
  cannot build up.
- **Tones:** the same notes as `src/platform/audio.js` (triangle waves, same
  frequencies, durations and click-free ramps), synthesized to PCM once and
  played through `AudioTrack`, scaled by beep or fanfare volume.
- **Voice:** `TextToSpeech` at rate 1.5, locale from the app language
  (the first available of `VOICE_LOCALES`), volume per utterance. Initialized when the service
  starts so the first cue is not late.
- **Audio focus:** all audio uses `USAGE_ASSISTANCE_NAVIGATION_GUIDANCE`.
  Each cue group (a tone and any speech at the same moment) requests
  `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` and abandons it when tone and speech
  have finished. A single constant (`USE_AUDIO_FOCUS`) disables focus
  requests, so cues play over other audio without ducking.
- **Ordering:** a tone and speech at the same moment play tone first, then
  voice. Countdown pips always fire on time, even if speech is still going.

### Manifest permissions

`FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`,
`POST_NOTIFICATIONS`, `WAKE_LOCK`, plus a `<queries>` entry for the
`android.intent.action.TTS_SERVICE` intent (Android 11+ package visibility,
without which `TextToSpeech` cannot bind to the engine).

### Failure behavior

- No TTS voice for the locale: use the default voice. No TTS engine at all:
  tones still play.
- Notification permission denied: the service still runs.
- Plugin call rejects: the controller falls back to the web engine.

## 3. Build and install

- npm scripts: `android:sync` (`vite build && cap sync android`) and
  `android:build` (sync, then `gradlew assembleDebug` with `JAVA_HOME` set to
  Android Studio's bundled JDK).
- Install with `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`.
- README gets an "Android app" section: prerequisites (Android Studio 2025.2.1+
  with its SDK), USB debugging, build, install and the manual phone test.
- The Pages workflow is unchanged.

## 4. Testing

### Automated (vitest, test-first)

- `tests/core/timeline.test.js`: order and offsets, speech at every phase
  start with correct seconds, finish tone and finish speech, muted kinds
  filtered (voice 0 means no speech), mid-phase start, paused and finished
  sessions return `[]`, skipped time, `announceCurrent`, intense-style
  extras, tone before speech at equal `inMs`.
- A test for the pure function that resolves speech events to text
  (Portuguese and English output).

### Manual (real Android phone)

1. Start Semana 1 · Dia 1, lock the screen, wait through two phase changes:
   voice and beeps arrive on time.
2. YouTube playing in the foreground, PulseRun in the background: each cue
   ducks YouTube, then it returns. If YouTube pauses instead, set
   `USE_AUDIO_FOCUS = false` and retest.
3. Pause, resume and skip in the app, then lock again: cues follow the new
   timing.
4. Remove the app from recents mid-workout, reopen, resume from the dialog:
   cues resume.
5. Leave the phone locked for a full 30+ minute workout: no cue missed or
   more than about one second late.

## Success criterion

Manual tests 1, 2 and 5 pass on the user's phone during a real treadmill
session. If they do not, revisit the full native rewrite with a record of
what failed.

## Out of scope

iOS, Play Store, CI APK builds and signing, lock-screen timer or media
controls, UI changes.
